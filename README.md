# 专业监控工具

用于监控 Facebook 公共主页的粉丝增长、最近发帖时间、主页活跃情况与异常预警的桌面工具。

当前版本：**v1.5.0**

## v1.5.0 更新日志

- 软件名称统一改为「专业监控工具」。
- 「设置中心」精简为「设置」，删除恢复默认巡检参数、打开运行日志、重置窗口布局三个旧实用工具。
- 设置新增「智能维护 / 智能清理缓存」：扫描旧更新缓存、中断临时文件和过大的运行日志，确认后再清理；不会删除专业 ID、通知、头像、设置、数据库或浏览器连接记录。
- 专业 ID 管理入口统一改为「FB专业ID管理」。
- 主题调整为「蓝橙曜石（默认） / 石墨黑 / 清爽白 / 护眼绿」，删除深海蓝。
- 更新提示不再提供“前往发布页”按钮。发现新版时只提供「升级 / 以后再说」；下载并校验完成后再次确认「现在更新 / 以后再说」。
- 有新版等待处理时，主界面右上角更新按钮进入橙色强调状态。
- Windows 改用自定义中文部署器：默认 C 盘为标准安装模式；选择非 C 盘时自动切换绿色便携模式。
- Windows 标准模式写入当前用户卸载注册项，可在 Windows 应用列表 / Geek Uninstaller 中正常卸载。
- Windows 绿色便携模式不写卸载注册项，程序与数据都保存在选择的目录内，仅创建桌面快捷方式。
- 标准模式与便携模式都支持同一套静默升级流程；便携升级原地覆盖程序文件并保留 `data` 数据目录。
- GitHub 云端发布改为三个用户下载包：Windows x64、macOS arm64、macOS x64。每个 ZIP 只包含当前系统部署/安装文件和浏览器插件，不包含源码和 README。
- 云端构建继续预留 Windows Authenticode、Apple Developer ID 与 macOS notarization；正式自动升级需要发布者配置可信数字签名。

## Windows 使用方法

### 标准安装模式（C 盘）

1. 解压 `ProfessionalMonitorTool-1.5.0-windows-x64.zip`。
2. 运行其中的 `ProfessionalMonitorTool-1.5.0-windows-x64-deployer.exe`。
3. 默认目录位于当前用户的 C 盘应用目录，也可以自行选择其他 C 盘目录。
4. C 盘部署自动使用「标准安装模式」，创建桌面快捷方式并写入卸载登记。

### 绿色便携模式（非 C 盘）

1. 在部署器中选择 A/B/D/E 等非 C 盘目录。
2. 部署器会自动显示「绿色便携模式」。
3. 软件文件会直接展开到选择目录，并创建桌面快捷方式。
4. 不写 Windows 卸载注册项，因此不会作为正常安装应用登记到 Windows的标准卸载列表。
5. 便携模式的数据默认保存在软件目录的 `data` 文件夹中，移动或备份时更直观。

> 绿色便携模式的含义是“不注册为已安装应用”，不是隐藏文件。知道实际目录的人仍然可以看到程序文件。

## macOS 使用方法

Release 提供两个单独 ZIP：

- Apple Silicon（M1/M2/M3/M4 等）：`ProfessionalMonitorTool-1.5.0-macos-arm64.zip`
- Intel Mac：`ProfessionalMonitorTool-1.5.0-macos-x64.zip`

解压对应 ZIP，安装其中的 PKG。

## Chrome 浏览器连接器

三个平台 ZIP 都自带 `浏览器插件` 文件夹。

1. 打开 Chrome：`chrome://extensions`
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择 ZIP 解压后的 `浏览器插件` 文件夹。
5. 打开专业监控工具和需要用于巡检的 Chrome Profile，连接器会在同一台电脑上自动发现软件，无需配对码。
6. 一个连接器在线时自动使用；多个连接器在线时可在软件右上角「浏览器」中单选或多选，并行分配任务。

## 巡检与数据

- 软件启动默认不自动巡检，除非用户在设置中明确开启。
- 默认每轮基准间隔 120 分钟，并随机提前或延后 15–25 分钟。
- 两个主页之间默认随机等待 6–9 秒。
- 页面名称、头像、粉丝数据和最近发帖时间由浏览器连接器读取。
- 设置与数据会跨重启保留。
- 绿色便携模式默认把数据保存在程序目录下；标准模式继续使用正常用户数据目录。

## 更新

软件只提示正式稳定版本。发现新版后：

1. 显示版本号和更新日志。
2. 用户点击「升级」后在后台下载当前系统对应 ZIP。
3. 完成 SHA-256 校验并提取当前系统部署/安装文件。
4. 再次询问「现在更新 / 以后再说」。
5. 用户确认后才退出当前程序并执行升级。

Windows 正式自动升级要求更新部署器具有受信任 Authenticode 数字签名；macOS 正式自动升级要求 Developer ID 签名和公证。未配置可信签名的测试构建不会自动执行下载的安装文件。
